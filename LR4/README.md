## Призначення
Консольна програма з меню для ведення списку книжок (`struct Record`). Кожний запис містить назву книги (`name`, 1..60 байтів після обрізання крайових пробілів) та кількість сторінок (`pages`, ціле число від 1 до 50). Колекція містить від 0 до 30 записів.

## Пункти меню
- `0` — Вихід із програми (без автоматичного збереження)
- `1` — Додати новий запис (із повною перевіркою полів до мутації вектора)
- `2` — Переглянути всі записи колекції
- `3` — Регістрозалежний пошук усіх збігів за підрядком назви
- `4` — Редагувати один запис за порядковим номером `1..size` через тимчасовий об'єкт
- `5` — Завантажити колекцію з текстового файла `variant01_books.txt` через тимчасовий вектор
- `6` — Зберегти поточну колекцію у файл `variant01_books.txt`

## Середовище, збірка та робоча тека
- Робоча тека проєкту повинна містити файл `variant01_books.txt` (у Visual Studio: `Working Directory: $(ProjectDir)`).
- Компіляція через `g++`:
```bash
g++ -std=c++17 main.cpp -o bookshelf.exe
./bookshelf.exe
```

## Формат файла та обмеження
- Перший рядок файла `variant01_books.txt` — ціле число `count` (`0..30`).
- Далі йдуть `count` пар рядків: назва книги (`1..60` байтів без CR/LF) та кількість сторінок (`1..50`).
- Порожній файл (0 байтів), неповні записи, числа з дробами/зайвими токенами або непорожній хвіст після записів відхиляються зі збереженням попередньої колекції в пам'яті.

## Основні перевірки (Варіант 1)
1. Завантаження початкових записів: `Cedar Tales` (7), `Cedar Road` (12), `Moon Map` (19).
2. Пошук `Cedar` -> знаходить №1 та №2; `Moon Map` не збігається.
3. Успішне редагування №2 на `Cedar Atlas` (24 сторінки).
4. Спроба редагування №2 на `0` сторінок -> відмова, залишається `Cedar Atlas` (24).
5. Ручне збереження (6), перезапуск та повторне завантаження (5) підтверджують збереження порядку й полів.
